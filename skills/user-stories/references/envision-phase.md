# AI-DLC 構想フェーズ詳細リファレンス

## 構想フェーズの位置づけ

構想フェーズはAI-DLCの最初のフェーズであり、ビジネス意図を開発可能な形に変換する。
主要なイベントは「モブエラボレーション」であり、ファシリテーターが主導する
共有画面での協力的な要件詳細化セッションとして行われる。

## モブエラボレーションの流れ

### 参加者
- プロダクトオーナー（ビジネス意図の保持者）
- 開発者（技術的実現可能性の検証者）
- QA（テスト可能性の検証者）
- その他関連ステークホルダー
- AI（中心的な役割：分解と提案を主導）

### AIの役割

AIはモブエラボレーションにおいて以下を主導する：

1. **明確化質問の生成** — 意図の曖昧さを特定し、具体的な質問で解消
2. **初期分解の提案** — 意図をユーザーストーリー、受け入れ基準に分解
3. **NFRの特定** — ビジネス意図から派生する非機能要件を提案
4. **リスクの特定** — 技術的・ビジネス的リスクを洗い出し
5. **ユニット候補の提案** — 高凝集・疎結合の原則に基づくグルーピング案

人間は以下の役割を果たす：
- AIの提案をレビューし、過剰設計/過小設計を調整
- 実世界の制約との整合を確認
- ビジネス優先度の最終決定
- リスク許容度の判断

### 構想フェーズの出力

1. **ユーザーストーリー** — INVEST基準を満たす、ボルト粒度のストーリー
2. **受け入れ基準** — 各ストーリーの検証可能な完了条件
3. **NFR定義** — パフォーマンス、セキュリティ、可用性などの非機能要件
4. **リスク説明** — 組織のリスク登録簿と整合したリスク記述
5. **PRFAQ（オプション）** — ビジネス意図、機能、期待される利益の要約
6. **測定基準** — ビジネス意図に追跡可能なKPIや成功指標

## AI-DLCの主要原則（構想フェーズに関連するもの）

### 会話の方向を逆転させる
従来：人間がAIにタスクを依頼 → AI-DLC：AIが人間に提案・質問し、人間が承認

Googleマップの類推：
- 人間 = 目的地（意図）を設定する人
- AI = ルート（計画）を提案し、ステップバイステップで案内するシステム
- 人間は途中で監視し、必要に応じてルートを調整

### 人間との共生を強化するものを維持する
ユーザーストーリーは人間とAIの理解を整合させる契約として機能する。
AI-DLCでもユーザーストーリーを維持するが、リアルタイム使用に最適化する。

### ボルト粒度
従来のスプリント（2〜4週間）ではなく、ボルト（時間〜日単位）で完了可能な粒度。
ストーリーはこのサイクルで実装・検証可能なサイズに分割する。

## グリーンフィールド vs ブラウンフィールド

### グリーンフィールド（新規開発）
- 意図から白紙状態でストーリーを作成
- ドメインの境界を定義する自由度が高い
- 全体像の整合性に注意

### ブラウンフィールド（既存システム変更）
- 既存システムのコンテキストを考慮
- 既存のドメインモデルとの整合性が必要
- 技術的負債の影響を評価
- 構想フェーズの活動自体はグリーンフィールドと同じ
